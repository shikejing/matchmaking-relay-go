# 中继会话生命周期（Relay Session Lifecycle）

实现见 `session` 包。所有对外读取都通过一次加锁返回
`SessionSnapshot`：会话状态与完整成员集合是同一个自洽快照，不存在
“状态已改、成员没改完”的半更新视图；成员列表按玩家 ID 排序，快照可
直接对比。

## 1. 状态机

```
            全部成员至少 Join 一次
 gathering ─────────────────────────▶ active
     │                                │  │
     │（驱逐/关停/空场）                │  │ 任一成员掉线
     ▼                                │  ▼
  closed                              │ degraded
      ▲                               │  │
      └───────────────────────────────┘  │
                                         │ 窗口内重连 / 补位完成
                                         └▶ active（或 gathering 等新成员加入）
                                         │ 窗口超时按策略处理
                                         └▶ closed
```

- `gathering`：会话已建立，等待初始成员连接；成员已按匹配结果
  预占席位，但尚未到齐。
- `active`：全体成员到齐且在线，中继正常转发。
- `degraded`：有成员掉线且处于保留窗口内。
- `closed`：终态。`CloseReason` 区分：`normal`（正常/全员离开）、
  `disconnect_timeout`（超时结束策略）、`backfill_failed`（补位失败）、
  `evicted`（关停/管理器驱逐）。

成员状态：`present` / `disconnected` / `removed`。

## 2. 加入、离开

- 会话创建时成员席位已确定；`Join` 把某条内存管道绑定到席位。
- 未知玩家加入被拒绝；对同一玩家重复 `Join/Reconnect` 只是替换其
  管道，成员总数始终按玩家 ID 计一次，不会重复计数。
- `Leave` 主动离开：移除席位；当活跃成员集合变空，会话以 `normal`
  关闭。

## 3. 掉线与重连

1. 客户端管道关闭（`Peer.Disconnect()` 模拟网络掉线）后，会话的
   转发泵感知到管道关闭，把成员置为 `disconnected` 并记录掉线时刻，
   会话进入 `degraded`。
2. 在 `ReconnectHoldMs` 保留窗口内，可用新管道 `Reconnect`：
   - 成功则恢复为 `present`，全体在线时回到 `active`；
   - 窗口外重连、对已移除席位重连、在线状态下重复重连都会得到可
     区分的拒绝结果，不会产生中间状态。
3. 窗口超时后的策略（`config.ReconnectPolicy`）：
   - `end_session`：整局关闭，原因 `disconnect_timeout`；
   - `hold_slot`：无限保留席位，会话保持 `degraded` 等待重连；
   - `backfill`：**以队伍为单位**处理——掉线成员所属整队的席位被
     移除，并按“最早入队、人数恰好相等、规则版本相同”的确定性顺序
     从同分区队列取一支替补队注入；会话回到 `gathering` 等待替补
     玩家加入。若没有合格替补，会话以 `backfill_failed` 关闭。
     替补查找发生在会话锁之外（通过 `FillFunc` 回调），不会与队列
     自身的匹配死锁。

## 4. 消息中继

- 内存回环管道（`transport` 包）模拟客户端连接，全程无外部服务。
- 发送带 `To` 为定向消息，否则广播给除发送者外的全体在线成员。
- 所有管道发送都是**非阻塞**的：管道有界，满或已断开时发送失败，
  慢消费者不会拖死会话，内存也不会无界增长。

## 5. 一致性要点

- 队列→会话的移交与会话内成员状态迁移分别由分区锁与会话锁保护；
- 管理器（`Manager`）的 `Snapshot()` 对每个会话取其原子快照，并按
  会话 ID 排序输出；
- 会话结束时先写 `session_closed` 审计再对外可见为终态，历史可查。
