# 匹配语义（Matchmaking Semantics）

本文档说明组队匹配的裁决规则、确定性与可复现性保证。实现见
`queue`、`match`、`rules` 三个包。

## 1. 队伍是不可拆分的原子单位

- 提交单位是队伍（`types.Team`），包含一名或多名玩家。
- 匹配只在“整队”之间组合，任何队伍都不会被拆散，也不会与其他队伍
  的个别成员重新编组。
- 一个分区内：
  - 同一 `TeamID` 只允许入队一次，并发或重复提交只产生一条队列记录，
    重复提交得到 `duplicate_team` 拒绝结果；
  - 同一 `PlayerID` 在同一分区内只能属于一条在队队伍，违反得到
    `player_already_queued`。
- 入队时由当前分区所属规则版本的 `MergeScore` 计算队伍分值，随队列
  记录冻结，之后规则升级不改变它。

## 2. 分值合并规则（按版本）

| 版本 | 队伍分值 | 说明 |
|------|----------|------|
| v1 | 成员分值的四舍五入算术平均值 | `round(sum/n)` |
| v2 | 成员分值的中位数 | 偶数人数取较大的中位值（upper middle） |

版本差异可通过 `rules.Rules.Describe()` 与 `Engine.PartitionRules()`
查询追溯；已入队队伍与已建立会话始终沿用其进入时的版本。

## 3. 匹配优先依据与裁决顺序

一次 tick 对一个分区执行：

1. **输入顺序固定**：队列严格按全局单调递增的提交序号（FIFO）读取，
   任何地方都不依赖 Go map/set 的遍历顺序。
2. **锚点顺序固定**：从队首开始依次取未被使用的队伍作为锚点；
   人数本身超过目标人数的队伍无法成局，跳过（继续等待）。
3. **候选枚举固定**：对每个锚点，用“按下标递增的深度优先搜索”枚举
   后续窗口（`SearchWindow`）内可以与其恰好凑成 `TargetTeamSize`
   人的队伍子集；枚举顺序只取决于下标，与运行时随机化无关。
4. **候选裁决（优先级从高到低）**：
   1. **等待时长优先（耐心，防止饥饿）**：候选中“最老队伍”的入队
      时长越大越优先；
   2. **分值接近度优先**：等待时长相同时，候选内队伍分值极差
      （max−min）越小越优先；
   3. **字典序兜底**：仍相同时，按队伍 ID 排序后的元组字典序裁决
      （与枚举/哈希顺序无关）。
5. **分值软屏障（soft barrier）**：默认要求分值极差
   `<= ScoreWindow`；但当候选中最老队伍已等待 `>= MaxWaitMs` 时，
   屏障对该候选放开，保证任何队伍在等待足够久后都不会被分值差距
   永久挡住。
6. 选定最优候选后，其队伍在**同一把分区锁内**从队列原子移除并创建
   会话；然后推进到下一个空闲锚点。每个 tick 最多创建 `MaxBatch`
   个会话。

搜索是有界的：`SearchWindow`、`MaxCandidatesPerAnchor`、
`MaxSearchNodesPerTick` 共同限制单次 tick 的 CPU；截断也按固定的
下标顺序发生，因此仍然可复现。

## 4. 确定性与可复现性保证

在以下条件下：

- 相同配置（含 `RandomSeed` 与所有阈值）；
- 相同的入队顺序（相同提交序号顺序）；

**任意并发度、任意重复运行次数都会得到逐条一致的匹配结果**：

- 提交序号由 `Engine` 的全局原子计数器分配，并发提交具有全序；
- 每个分区的 tick 在分区互斥锁内完成“读队列→决策→移除→建会话”，
  并发 tick 被串行化，不可能交错产生半成品结果；
- 所有排序使用显式比较器（稳定排序 + ID 字典序兜底），代码中没有
  任何影响输出的 map 遍历，也没有使用运行时随机源；
- `RandomSeed` 预留给未来仍需确定的随机规则，当前裁决不消耗随机性。

测试见 `match/match_test.go`（含 200 次重复一致性、耐心优先级、
软屏障）与 `engine/engine_test.go`（8 路并发 tick 结果一致）。

## 5. 每次匹配的审计

每次成局写入 `matched` 审计事件（每个成组队伍一条，可从队伍或会话
两侧追溯），`Detail` 记录成组队伍及其冻结分值与提交序号，例如：

```
t01(score=100,seq=1),t02(score=101,seq=2)
```

结合该 tick 的输入快照与 `rules.Rules.Describe()`，可完整复盘当时的
输入与裁决依据。
